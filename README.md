# Распознавание действий человека по изображениям

Курсовой проект по компьютерному зрению, целевой уровень — «4».
Задача: по одной фотографии определить одну из 15 категорий действий.
Это классификация изображений, а не анализ движения в видео.

**Статус:** код подготовки, обучения, сравнения, оценки и API подготовлен.
Обученных итоговых весов и результатов качества пока нет. Оценка зависит
от выполнения требований и защиты. До полного обучения согласуйте тему,
ResNet18 и предлагаемые модификации с преподавателем.

## Данные

Источник: [Human Action Recognition (HAR) Dataset](https://www.kaggle.com/datasets/meetnagadia/human-action-recognition-har-dataset).
Скачайте и распакуйте датасет так:

```text
Human Action Recognition/
  Training_set.csv
  Testing_set.csv
  train/
  test/
```

В проверенной локальной таблице `Training_set.csv`: 12 600 строк, 15 классов,
по 840 примеров каждого класса. Столбцы: `filename,label`.
В `Testing_set.csv`: 5 400 строк и только `filename`, без истинных меток.
Поэтому каталог Kaggle `test` не используется для расчёта качества.
Он пригоден для демонстрации предсказаний без оценки их правильности.

Подготовка проверяет декодирование изображений, SHA-256 файлов,
хеши декодированных пикселей и pHash. Связанные группы копий и похожих
изображений целиком попадают в одну выборку. Группы с противоречивыми
метками исключаются и перечисляются отдельно. Разбиение выполняется по
группам с учётом классов, приблизительно 70/15/15. Фактические количества
смотрите в `data/splits/summary.json`. pHash — эвристика: требуется просмотреть
подозрительные группы; он не гарантирует выявления всех похожих сцен.
Состав выборок сохраняется в CSV; повторная подготовка поверх готового
разбиения запрещена, чтобы не поменять тестовую выборку случайно.

## Метод и эксперименты

Основа — готовая `torchvision.models.resnet18` с ImageNet-весами.
Вся сеть дообучается, финальный классификатор выдаёт 15 логитов.

| Вариант | Отличие от исходной модели | Проверяемая гипотеза |
|---|---|---|
| baseline | Стандартный Global Average Pooling | Исходный уровень качества |
| gem | Обучаемое степенное усреднение GeM | Усиление локальных активаций может помочь различать действия |
| avgmax | Конкатенация среднего и максимума; вход классификатора 1024 вместо 512 | Общий контекст и локальные признаки могут дополнять друг друга |
| attention | Обучаемые пространственные веса усреднения | Выбор значимых участков может уменьшить влияние фона |

Самостоятельно реализованы три pooling-модуля, подготовка данных,
обучающий цикл, интеграция с трекером, выбор модели, оценка и API.
Backbone ResNet18 и предобученные веса взяты из torchvision.
Замена числа классов нужна для задачи, но не считается модификацией на «4».

**Основная метрика — macro F1:** каждый класс получает одинаковый вес,
учитываются precision и recall. Дополнительные метрики: accuracy и cross-entropy.
По эпохам сохраняются train/validation loss, macro F1 и accuracy.
Train-метрики вычисляются во время обучения на аугментированных изображениях;
validation/test — в режиме eval без случайных преобразований.

Все конфигурации используют один seed, одинаковые выборки, разрешение 224,
12 эпох, AdamW, lr=0.0001, weight decay=0.0001 и batch size=32.
Классификатор avgmax содержит больше параметров — это часть модификации,
а не скрытое изменение эксперимента. Для вариантов с одинаковой шириной
головы её начальная инициализация при одном seed одинакова.
Детерминированные операции включены, но побитовая идентичность между
разными устройствами и версиями библиотек не обещается.

Выбор лучшей эпохи и модели выполняется только по validation macro F1.
Если модификации не улучшают baseline, требования предусматривают минимум
три разных обученных модификации. Поэтому предусмотрены все три варианта.
Неудачные и пробные запуски также нужно сохранить в MLflow и описать в отчёте.

## Требования к запуску

- Docker с Linux containers и Docker Compose.
- Интернет при первой сборке для зависимостей и при первом обучении для ImageNet-весов.
- Достаточно места для датасета, образа, весов и трекера; образ с PyTorch большой.
- CPU поддерживается, но полное обучение четырёх сетей может занять значительное время.
- Для ускорения: NVIDIA GPU, совместимый драйвер и NVIDIA Container Toolkit
  на Linux либо GPU-поддержка Docker Desktop/WSL2 на Windows.
  Зависимости используют PyTorch 2.5.1; проверьте совместимость GPU с этой версией.

Python на машине проверяющего не нужен: все команды ниже выполняются в контейнерах.
Прямые зависимости зафиксированы в `requirements.txt`, базовый образ — в Dockerfile.

## Запуск по шагам

Команды выполняются из корня проекта. На Windows запустите Docker Desktop
и дождитесь готовности Linux engine. Проверьте `docker info`.

Docker по умолчанию устанавливает CPU-версии PyTorch и torchvision из официального
индекса PyTorch: CUDA-библиотеки не скачиваются. Установка использует кэш pip,
таймаут 180 секунд и повторные попытки. Конфигурация `device: auto` на таком
образе выбирает процессор. Полное обучение на CPU может быть долгим; сначала
выполните smoke-проверку.

### 1. Сборка и проверка

```bash
docker compose build
docker compose run --rm tools -m unittest discover -s tests -v
```

### 2. Подготовка данных

```bash
docker compose run --rm tools -m har.prepare
docker compose run --rm tools -m har.verify_data
```

Если `data/splits/summary.json` уже создан и проверен, повторять подготовку не нужно.
Проверьте `duplicates.json` и `excluded.json`; окончательно зафиксируйте разбиение
до первого полноценного эксперимента. Изменение политики очистки требует новых
экспериментов и отдельного каталога разбиения.

### 3. Трекер и пробный запуск

```bash
docker compose up -d mlflow
docker compose run --rm train --config configs/baseline.json --smoke
```

MLflow: [http://localhost:5000](http://localhost:5000).
Каждый запуск получает `run_id`; локальные результаты — `outputs/runs/RUN_ID/`.
Smoke запускает две мини-партии train и validation, без ImageNet-весов, на CPU.
Он проверяет соединение компонентов, **не оценивает качество** и записывается
в отдельный эксперимент `HAR-smoke`. Выбрать его итоговой моделью нельзя.

### 4. Полноценное обучение

```bash
docker compose run --rm train --config configs/baseline.json
docker compose run --rm train --config configs/gem.json
docker compose run --rm train --config configs/avgmax.json
docker compose run --rm train --config configs/attention.json
```

Для NVIDIA используйте для каждого запуска такую форму:

```bash
docker compose build --build-arg PYTORCH_INDEX_URL=https://download.pytorch.org/whl/cu124
docker compose -f compose.yaml -f compose.gpu.yaml run --rm train --config configs/baseline.json
```

`device=auto` выберет CUDA, если она доступна внутри контейнера.
Для честного сравнения запускайте все варианты на одном устройстве.
Если меняете параметры из-за ограничений памяти, одинаково измените все
конфигурации **до** экспериментов. Не сравнивайте полный и smoke-запуск.

В MLflow сохраняются конфигурация, версия PyTorch, устройство, количество
параметров, состав и хеши выборок, код, метрики по эпохам, лучший checkpoint
и графики. Лучшие веса каждого запуска: `training/best.pt` в его артефактах.

### 5. Сравнение и фиксация выбранной модели

Подставьте реальные идентификаторы из MLflow/имён каталогов:

```bash
docker compose run --rm tools -m har.select --runs outputs/runs/BASELINE_RUN_ID outputs/runs/GEM_RUN_ID outputs/runs/AVGMAX_RUN_ID outputs/runs/ATTENTION_RUN_ID
```

Команда проверяет одинаковые условия и выборки, формирует
`outputs/final/comparison.csv` и `selection.json`, копирует победителя в
`outputs/final/model.pt`. Если GeM улучшил baseline, допускается указать
только baseline и GeM. Если улучшения нет, потребуются все три модификации.
При равенстве метрик предпочтение отдаётся первому указанному варианту.
Повторный выбор поверх `outputs/final` запрещён.

### 6. Единственная итоговая оценка на test

```bash
docker compose run --rm evaluate
```

Результаты: `test_metrics.json`, `classification_report.json`,
`confusion_matrix.png`, `predictions.csv`, `correct_examples.png`,
`error_examples.png`. Они также привязываются к исходному MLflow-запуску.
После просмотра test модель по этим результатам не подбираем.
Маркер `evaluation_started.json` блокирует случайное повторение; если произошёл
технический сбой, сначала разберите причину и зафиксируйте её, затем осознанно
восстановите оценку без изменения модели или выборок.

### 7. API с готовыми весами, без обучения

```bash
docker compose up -d api
```

Сервис не зависит от запущенного MLflow: для инференса достаточно
`outputs/final/model.pt` и `outputs/final/selection.json`.
Документация и загрузка изображения: [http://localhost:8000/docs](http://localhost:8000/docs).

В PowerShell используйте `curl.exe`, в Linux — `curl`:

```powershell
curl.exe http://localhost:8000/health
curl.exe -X POST http://localhost:8000/predict -F "file=@Human Action Recognition/test/Image_1.jpg"
```

`GET /health`: HTTP 200 только после загрузки весов и успешного пробного
прохода модели; ответ содержит `status` и `run_id`. При ошибке загрузки
процесс завершается, сервис не объявляет себя готовым.

`POST /predict`: multipart-поле `file`, изображение JPEG, PNG или WEBP,
до 10 MiB и 20 млн пикселей. Ответ:

```json
{
  "class": "sitting",
  "confidence": 0.71,
  "probabilities": {"calling": 0.01, "sitting": 0.71},
  "run_id": "actual_mlflow_run_id"
}
```

Это условный пример: настоящий ответ содержит **все 15 классов**,
сумма вероятностей равна единице. Вероятности softmax не являются гарантией
правильности или откалиброванной уверенностью.
Ошибки: HTTP 413 — превышен размер, 415 — неподдерживаемый формат,
422 — невалидное/отсутствующее изображение, 503 — модель не готова.
EXIF-ориентация и нормализация обрабатываются одинаково в оценке и API.

**Идентификатор эксперимента сервисных весов:** после выбора берётся из
`outputs/final/selection.json` → `selected.run_id`, проверяется через `/health`.
До сдачи впишите сюда реальный ID и ссылку из интерфейса MLflow.
На текущем этапе финального эксперимента ещё нет.

## Сохранение и передача

- `data/splits/` — состав выборок и аудит данных.
- `outputs/runs/` — веса, конфигурации и результаты обучения.
- `outputs/tracking/` — SQLite-база MLflow и его артефакты.
- `outputs/final/` — выбранная модель, происхождение и итоговая оценка.
- `torch-cache` — скачанные предобученные веса.

Каталоги подключены с хоста: удаление контейнеров не удаляет результаты.
Для сдачи приложите код, README, данные/инструкцию получения, `data/splits`,
`outputs/final`, `outputs/tracking` и заполненный отчёт. Проверяющий может
открыть переданный трекер через `docker compose up -d mlflow`, а API — отдельно.
Не удаляйте содержимое tracking до защиты. Не передавайте только веса
без `selection.json` и истории экспериментов.
